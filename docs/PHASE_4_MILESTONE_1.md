# Phase 4 Milestone 1: Validator-First Engram Scaffolding

Phase 4 Milestone 1 begins engrammatic emergence as a validator-first and evidence-first lane.

This milestone does not declare lawful engram admission. It defines the smallest stable scaffolding needed so identity-bearing forms can be discussed, inspected, and later validated without collapsing back into vague metaphor or jumping forward into runtime identity claims.

## Intent

Milestone 1 should answer questions like:

- what makes an artifact evidentiary support for a perspectival or participatory engram claim
- how should the repo distinguish lawful support from unsupported identity assertion
- what parts of an engram-support artifact can remain Prime-safe
- what provenance and constructor evidence must exist before a stronger claim is even discussable

## Scope

Milestone 1 includes:

- validator-first schema boundary notes for perspectival and participatory engram support artifacts
- a support-first working-intent transition model that stops short of Phase 5 decision semantics
- lawful and unlawful example definitions for engram-support corpora
- capture-profile alignment for `engram_root_constructor_capture`
- Prime-safe and privileged inspection expectations for identity-support artifacts
- initial comparison questions for root coherence, constructor traceability, and evidence sufficiency

Milestone 1 does not include:

- GEL or cGEL candidacy approval
- runtime identity continuity
- OE or Sanctuary participation
- commitment, covenant, or formation state
- async `.hogif` identity transport
- aesthetic or symbolic rendering beyond evidentiary support surfaces

## Required Preconditions

Before Milestone 1 begins:

- the Phase 3 single-clock release baseline must remain stable
- [`PHASE_4_ENTRY_CRITERIA.md`](./PHASE_4_ENTRY_CRITERIA.md) must define the active stop line
- [`PHASE_4_WORKING_INTENT_TRANSITIONS.md`](./PHASE_4_WORKING_INTENT_TRANSITIONS.md) must define the active stance ladder
- capture profiles must already distinguish engram-support evidence from constitutive authority
- admissible identity morphism law must remain available as a planning constraint rather than an ad hoc later fix

## Artifact Posture

Milestone 1 should treat Phase 4 artifacts as support artifacts first.

The first executable Milestone 1 slice now exists as machine-readable perspectival and participatory support sidecars that remain support-only, Phase 3-inheriting, and validator-bounded.

That slice now also machine-checks `intentClassification` and `supportShape` so the working-intent ladder is no longer prose-only when support artifacts are validated, inspected, or compared.

That slice now also exposes a deterministic stability-field summary during inspection so candidate support states can be ranked as low-energy or high-energy configurations without turning that score into new admission authority.

Initial artifact classes should remain in the posture of:

- candidate-support evidence
- constructor-trace evidence
- root-form coherence evidence

Those postures should mature through the working-intent ladder rather than jumping straight into later review or acceptance semantics.

They should not yet be treated as:

- admitted identity forms
- binding commitments
- runtime-governed participants

## Initial Milestone 1 Questions

The first validator-first questions should be:

- does the artifact declare whether it is perspectival or participatory support
- does the artifact preserve traceable provenance from observed basis to claimed structure
- does the artifact distinguish visible claim surface from protected constructor evidence
- can Prime-safe inspection describe the claim class without exposing protected identity material
- can the validator reject unsupported identity claims that lack constructor or provenance support

## Lawful and Unlawful Example Expectations

Milestone 1 should not proceed without example pairs.

At minimum it should define:

- one lawful perspectival-support example
- one unlawful perspectival-support counterfeit or unsupported example
- one lawful participatory-support example
- one unlawful participatory-support counterfeit or unsupported example

The purpose is to force the repo to define what counts as evidence for an identity-bearing form before stronger semantics are layered on top.

The milestone now has a committed public-safe example pair for each of those four classes plus lawful comparison peers for perspectival and participatory support, so support evidence, root or branch coherence, counterfeit pressure, and failure paths can be checked against a stable corpus rather than only scratch generation.

It also now has committed lawful negative-state corpora for `restricted_support`, `deferred_support`, and `rejected_support` so the repo can preserve boundary-bearing support states without flattening them into either success or failure.

## Working-Intent Stances

Milestone 1 should adopt the Phase 4 working-intent transition grammar in [`PHASE_4_WORKING_INTENT_TRANSITIONS.md`](./PHASE_4_WORKING_INTENT_TRANSITIONS.md).

At minimum, the milestone should be able to distinguish:

- `working_intent`
- `structured_intent`
- `supported_intent`
- `reviewable_support`
- `restricted_support`
- `deferred_support`
- `rejected_support`

The milestone should treat `reviewable_support` as the strongest positive Phase 4 stance, with any later `review / accept / defer / reject / restrict` decision grammar reserved for Phase 5.

Those stances are no longer documentation-only. The current support sidecars and comparison lane now machine-check the support-shape and intent-class markers needed to distinguish them.

## Inspection Surface

Milestone 1 should preserve the same inspection discipline that closed Phase 3:

- Prime-safe views expose claim class, provenance posture, and validation findings
- privileged views expose fuller constructor and coherence support
- no inspection path should silently upgrade support evidence into candidacy or authority

## Acceptance Criteria

- the repo can describe Phase 4 support artifacts without relying on Phase 3 temporal language alone
- lawful and unlawful Milestone 1 example classes are defined
- Prime-safe posture remains coherent for identity-support artifacts
- capture-profile guidance and Phase 4 milestone language agree
- working-intent stance transitions are explicit enough that support evidence is not mistaken for acceptance semantics
- lawful negative support states remain machine-checkable and corpus-backed rather than being inferred from free-text notes
- the milestone can be extended later without forcing redefinition of Phase 3 temporal law

## Non-Goals

- deciding whether a candidate should be admitted
- treating constructor evidence as sufficient authority
- defining covenant or commitment acts
- binding Phase 4 artifacts into runtime life

## Relationship To Later Work

Milestone 1 is the bridge.

Later Phase 4 work may deepen schema, comparison, and identity structure only after this milestone makes the evidentiary posture legible enough that stronger claims can be judged honestly.
