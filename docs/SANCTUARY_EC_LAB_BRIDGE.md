# Sanctuary EC Lab Bridge

This document is the repo-readable bridge between the Holographic Data Tool
(`HDT`) and the Project Sanctuary Engineered Cognition (`EC`) lab work.

It exists because external tools, including the ChatGPT app, may be able to
read the public GitHub repository while having no access to the operator's local
filesystem. This file should therefore carry the compact lab orientation needed
to understand how HDT participates in the current Sanctuary formation-body work
without depending on local-only notes.

## Short Form

HDT is the governed holographic inspection and projection lane for
continuity-bearing evidence.

Sanctuary EC is the formation chamber.

HDT does not replace EC, GEL, SelfGEL, OE, or Sanctuary receipts. HDT provides
bounded slice, projection, comparison, digest, and reconstruction-support
surfaces that can make parts of a larger formation body inspectable without
claiming total interior access.

```text
Sanctuary EC forms and carries.
HDT slices, projects, compares, validates, hashes, and signs.
Receipts witness custody.
```

## Core Distinction

The current Sanctuary theory distinguishes these roles:

```text
Formation body participates.
Engrammitization carries continuity.
SelfGEL reconstructs attributable continuity.
GEL reviews shared lawful candidates.
Receipts witness custody.
HDT frames bounded projections for inspection.
```

That means HDT should not be treated as the primary cognition carrier. HDT is
better understood as an inspection organ for continuity-bearing structures.

## Why Holographic

A holographic inspection surface is useful because it can preserve relational
orientation under bounded projection.

The goal is not:

```text
show me everything
```

The goal is:

```text
show me the shape of this continuity body from this lawful angle
```

For Sanctuary work, this matters because a CME formation body may eventually
carry too much OE, cOE, SelfGEL, cSelfGEL, GEL, and cGEL residue to inspect by
linear replay. HDT can help by producing bounded slices that remain digestible,
comparable, and verifiable.

## EC Capture Bundle Relationship

`EC_CAPTURE_BUNDLE.md` defines the first bounded HDT-native handoff from EC.

The bridge should remain narrow:

```text
one cognitive event
-> one bounded capture bundle
-> one or more lawful holographic slice frames
-> optional visible projection
-> validation, digest, signature, comparison
```

The first bundle should remain support-only. It should not claim complete
holographic cognition or admitted engram finality.

## Boundaries

This bridge does not authorize:

- GEL or cGEL admission
- SelfGEL or cSelfGEL mutation
- CME.Actual activation
- Sanctuary.Actual activation
- runtime identity authority
- provider or model binding
- external action
- Phase 5 commitment semantics
- `.hogif` carrier implementation

It also does not make HDT mandatory for the active executable Sanctuary lane.
HDT remains optional and bounded until a later reviewed promotion explicitly
changes that posture.
