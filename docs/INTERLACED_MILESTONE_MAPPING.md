## Root Reading Order

When the full interlaced stack is present, the reading order is:

1. `OAN Tech Stack` for executable present truth
2. `Documentation Repo` for stabilized doctrine, chapter uptake, and publication-facing interpretation
3. `GNOMERONACORDE` for first-run, certification, and pedagogy carriage
4. `Holographic Data Tool` for optional governed `.hopng` validation, inspection, and evidence comparison

That order matters.

HDT phases may strengthen evidence and artifact law, but they do not outrank executable truth in the active build lane by themselves.

## Return Rules

The following may lawfully return from doctrine or publication work into the active build lane:

- clarified architecture notes
- build contracts
- readiness notes
- packet summaries

The following may not lawfully return by documentation alone:

- branch or worktree truth override
- public-release claims ahead of executable proof
- mandatory `.hopng` dependence where the active build has not admitted it
- Phase 4 support evidence being treated as identity admission

## Mapping Consequence

The current milestone map should therefore be read in two layers at once:

- local HDT maturity
- wider-stack admissibility

Local HDT maturity is now ahead of wider-stack dependence.

That is healthy.

It means the repo can keep strengthening `.hopng` law, evidence, and comparison without forcing premature adoption into the active executable lane.

It also means the milestone map should be read carefully:

- Phase 3 Milestone 4 is deferred research because its timing law is not yet admitted into executable truth
- Phase 4 entry is active, but only as a bounded support-evidence lane
- later Phase 4, Phase 5, and Phase 6 remain blocked until support evidence can lawfully mature into review, commitment, and runtime authority through the wider stack
